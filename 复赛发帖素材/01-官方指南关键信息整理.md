## 二、复赛与初赛的三个关键不同

### 🔴 不同点一：交付物升级 —— 从「Demo」到「完整产品」
- **初赛**：交一个能跑、能展示核心想法的 Demo，证明创意成立即可
- **复赛**：交一个**功能完整、流程可跑通、体验稳定的正式产品**，评审会像真实用户一样从头到尾完整使用

### 🔴 不同点二：提交方式升级 —— 「公开 + 私密」双轨
- **初赛**：社区公开发帖，所有内容公开
- **复赛**：
  - **社区发帖（公开）**：只发「作品说明帖」，展示产品简介、演示视频、创作历程、TRAE 实践过程
  - **飞书问卷（私密）**：提交作品交付物（体验入口、源码包、安装包等）与组队信息，仅评审可见

### 🔴 不同点三：参赛形式升级 —— 支持组队
- **初赛**：仅限个人参赛
- **复赛**：允许组队，每队 **2–3 人**（含队长），队长必须是初赛晋级作品的所属选手

## 三、组队规则详解

### 3.1 组队资格
- **队伍人数**：2–3人（含队长），不允许超过3人
- **队长要求**：必须是该作品初赛晋级作品的所属选手，是队伍唯一官方对接人
- **队员资格**：无需参加过初赛，即使此前未报名也可作为队员加入
- **作品归属**：每支队伍只能围绕1个初赛晋级作品组队；一个晋级作品只能成立一支队伍
- **禁止重复参赛**：同一选手不得同时加入多支队伍，也不得既以个人身份、又以队员身份重复参赛同一作品

### 3.2 组队信息提交（飞书问卷中一并提交）
1. **队伍名称**
2. **队长信息**：社区昵称、TRAE UID、对应初赛晋级作品链接、联系方式（手机号）
3. **全部队员名单**：每位成员的真实姓名、TRAE UID
4. **成员分工**：简述每位成员在作品中的实际职责
5. **全员同意确认**：队长须确认全部成员已知悉并同意参赛规则

> ⚠️ 若到截止时间仍未提交组队信息，则**视为该作品以队长个人身份参赛**，其他口头/私下约定的成员不予承认。

## 四、作品交付标准（⚠️ 核心要求）

### 4.1 复赛合格作品的最低标准

1. **延续初赛 Demo**：与初赛创意方向一致的完整作品，不是另起炉灶的新项目
2. **TRAE 开发**：必须完全由 TRAE IDE 或 TRAE Work 开发，并能提供可核验的开发过程材料
3. **功能完整**：具备完整的用户使用路径、齐全的核心功能与必要页面，结构稳定可靠、核心流程可顺畅走通
4. **部署上线**：
   - **软件类作品**：必须部署上线/可被评审直接访问体验
   - **硬件类作品**：已做出可真实运行的实物
5. **技术可验证**：技术架构清晰，AI 链路可验证，**任务 Session ID 不少于 3 个**

### 4.2 按作品形式的体验入口要求

| 作品类型 | 体验入口要求 | 备注 |
|----------|-------------|------|
| **Web 应用** | 在线链接（已部署） | 可用 Vercel、Netlify、GitHub Pages、Cloudflare Pages 等免备案托管 |
| **小程序** | 开发版/体验版二维码 | 无需发布上线 |
| **App (Android)** | APK 安装包 | 无需上架商店 |
| **App (iOS)** | TestFlight / 内测包 | 无需上架商店 |
| **硬件** | 完整演示视频（1-5分钟） | 需能看出是真机运行、非渲染或概念演示 |

**统一要求（所有作品类型）**：
- ✅ 必须额外提交一段**产品演示视频**（1-5分钟录屏，清晰展示核心流程）
- ✅ 如涉及登录/付费/权限，务必提供**测试账号/体验权限**
- ✅ 所有链接/安装包/视频需在整个评审期持续有效、可公开访问、无需额外申请权限
- ✅ **API Key 安全**：不得将真实 API Key 明文写入文档、演示视频或提交包；录屏中涉及密钥的画面请打码
- ✅ 源码非必交项，但主办方有权要求补交以核验原创性

### 4.3 从 Demo 到完整产品的升级方向

| 维度 | 初赛要求 | 复赛要求 |
|------|---------|---------|
| **核心目标** | 打动评审，证明创意可行 | 可被真实使用，评审会从头到尾完整使用 |
| **功能与页面** | 跑通1条核心链路即可 | 核心功能齐全、必要页面完备，具备完整用户路径 |
| **稳定性** | 能演示、可交互即可 | 结构稳定可靠，核心流程顺畅、无严重bug |
| **体验形式** | 链接/视频/可交互HTML | 真实可访问、可独立运行的体验环境 |
| **必备材料** | 简介、创作思路、体验入口、TRAE实践过程 | 在初赛基础上**新增**：产品说明书、完整产品演示视频、更完整的TRAE实践证明（Session ID ≥ 3个） |

## 五、提交方式详解（⚠️ 缺一不可）

### 5.1 第一步：社区发帖（公开展示）

**发布位置**：社区【复赛专区】

**发帖模板**：

| 项目 | 要求 |
|------|------|
| **类别** | 【TRAE AI 创造力大赛 - 复赛专区】 |
| **标签** | 必须四选一：`生活娱乐` / `学习工作` / `社会服务` / `硬件交互`；参加可选赛题可额外选择社会公益标签 |
| **标题** | 参赛赛道 + 作品名称 |
| **内容** | 产品简介、演示视频、创作历程、TRAE 实践过程 |

**正文必须包含的内容**：

1. **自己/团队介绍**
   - 个人：你是谁、为什么想做这个作品、擅长什么、Vibe Coding/编程年限、年龄（可选）、性格特点标签
   - 团队：队伍名称与定位、每位成员的角色与分工、团队的独特优势或协作故事
   - *本部分不计入评分，但会影响后续优秀作品展示与推荐*

2. **产品简介（复赛版，区别于初赛 Demo）**
   - **是什么**：一句话说清产品形态与解决的核心问题
   - **面向谁**：核心目标用户与典型使用场景
   - **完整功能**：完整的功能清单与用户使用路径，建议配产品截图、功能流程图（对应「产品完成度」）
   - **相比初赛 Demo 的升级**：简述从 Demo 到复赛成品，新增或打磨了哪些功能与体验

3. **产品演示视频**
   - 1-5分钟录屏，清晰展示产品的完整核心流程与亮点
   - 可贴抖音、Bilibili 等第三方平台公开链接，不要求专业剪辑

4. **产品创作历程**
   - 讲述作品从想法诞生 → 初赛 Demo → 复赛完整作品的演进过程
   - 包含：最初灵感来源、过程中遇到的关键问题与解决思路、重要的设计与技术决策（对应「创新性-解决思路」）

5. **TRAE 实践过程**
   - 清晰展示使用 TRAE 完成产品开发的完整流程
   - 附**开发关键步骤截图（不少于 3 张）**
   - 附**关键任务对话的 Session ID（不少于 3 个）**，用于证明作品确由 TRAE 开发完成

**加分建议**：
- 技术方案分享（技术栈、关键实现思路，对应「技术实现」）
- 商业化或社会价值分析
- 产品迭代规划

> ⚠️ **严禁在社区帖内放置**：可下载的源码包、安装包、固件包、可直接打开的作品文件、体验链接、二维码、测试账号（这些走飞书问卷）。

### 5.2 第二步：飞书问卷（私密提交）

**填写入口**：[TRAE AI 创造力大赛 · 复赛作品与组队信息提交问卷](https://bytedance.larkoffice.com/share/base/form/shrcnyi5hcPmbd5gKuhr44IET5f)

**问卷需提交的内容**：

1. **基本信息**：队长社区昵称、社区作品链接、参赛赛道、对应初赛晋级作品链接
2. **组队信息（如组队）**：队名、队长、全部成员名单、成员分工
3. **作品体验入口（私密，仅评审可见）**：
   - 按作品类型对应提交（体验链接 / 体验二维码 / 安装包 / 固件包等）
   - 附测试账号、打开说明
   - 源码包为选交项，可自愿提供或应主办方核验要求补交
4. **产品演示视频**：同社区说明帖内容，在问卷内同步存档（1-5分钟录屏，附第三方平台公开链接或上传问卷）

> ⚠️ **只做第一步、未填问卷 = 未完成复赛提交，不进入评审！**  
> ⚠️ 问卷中需回填你的社区帖链接，因此请**先发帖、再填问卷**。

## 六、评审标准（⚠️ 评分重点）

### 6.1 通用赛道评分维度

复赛全程采用**专家人工评审**，更侧重**产品的完整性与技术实现**。

| 评分维度 | 权重/说明 | 评审重点 |
|----------|----------|---------|
| **产品完成度** | 核心 | 功能是否完整、核心流程是否跑通、是否达到可真实使用的标准 |
| **创新性** | 核心 | 解决思路是否新颖、产品定位是否独特、差异化价值 |
| **技术实现** | 核心 | 技术架构清晰度、AI链路可验证性、代码质量 |
| **用户体验** | 核心 | 界面设计、交互流程、易用性、视觉品质 |
| **TRAE 实践** | 核心 | TRAE 使用深度、开发过程可核验性（Session ID ≥ 3个） |
| **社会价值** | 附加（社会服务赛道） | 对社会问题的关注度、解决方案的有效性、可持续性 |

### 6.2 评分要点提示

- **评审以飞书问卷提交的作品为准**，社区说明帖仅作公示与交流，不单独评分
- 只发社区帖、未提交飞书问卷的，视为未完成复赛提交，**不进入复赛评审**
- 问卷信息与社区昵称 / TRAE 账号需保持一致，否则可能导致资格校验失败或奖励无法发放
- 提交截止后不得擅自补交、替换、撤回或修改

# 丹青有AI · 复赛核心升级方向

> **制定依据**：复赛官方指南评分标准 + 项目当前实际进展 + 剩余时间评估（约16天）  
> **制定时间**：2026-07-24  
> **目标**：在有限时间内最大化复赛评分竞争力

---

## 升级方向一：接入真实AI能力，解决"模拟感"问题 🔴 最高优先级

### 现状问题
当前AI诊断、灵感嫁接、情绪画布三大核心功能均为前端模拟实现：
- 诊断结果是基于规则的随机数生成，缺乏真实图像分析
- 灵感嫁接的融合结果是占位符/预设图片，无真实融合效果
- 情绪画布的情绪到图像转换是色板预设，非AI生成

### 复赛评分影响
| 评分维度 | 影响程度 | 说明 |
|----------|---------|------|
| **产品完成度** | 🔴 严重 | 评审会真实体验产品，模拟功能容易被感知，影响完成度评分 |
| **技术实现** | 🔴 严重 | 技术架构中"AI链路可验证"是核心要求，纯前端模拟难以通过 |
| **创新性** | 🟡 中等 | 如果功能只是模拟，创新性的落地价值会被质疑 |
| **用户体验** | 🟡 中等 | 用户期待看到真实的AI分析结果，模拟结果会降低信任感 |

### 升级策略

**方案A：接入TRAE IDE内置AI绘图API（推荐，成本最低）**
- 利用项目中已有的 `imageService.ts` 基础
- 在情绪画布和灵感嫁接中接入真实图像生成
- 优点：无需额外API Key，国内可访问，与开发工具一致
- 缺点：生成速度和质量可能不如专业API

**方案B：接入火山引擎/豆包大模型API**
- 使用图像分析API实现真实诊断
- 使用图像生成API实现真实融合和情绪生成
- 优点：能力更强，分析更精准
- 缺点：需要申请API Key，可能产生费用，需处理鉴权

**方案C：优化前端模拟算法（保底方案）**
- 如果接入真实AI时间不足，大幅优化模拟算法
- 基于图片实际特征（尺寸、色彩分布等）生成"看似真实"的分析结果
- 增加更多变量和随机性，让每次分析结果不同
- 优点：实现快，无需外部依赖
- 缺点：仍是模拟，可能被经验丰富的评审识别

### 建议执行方案
**采用 A + C 组合策略**：
1. **情绪画布**：接入TRAE内置API实现真实图像生成（已有基础，最快实现）
2. **灵感嫁接**：接入TRAE内置API实现真实融合效果
3. **AI诊断**：优化前端模拟算法，基于图片实际特征生成分析结果（保底）
4. 如有时间，再接入后端分析服务实现真实诊断

### 预期效果
- ⬆️ 产品完成度评分提升 20-30%
- ⬆️ 技术实现评分提升 25-35%
- ⬆️ 用户体验评分提升 15-20%
- ⬆️ 整体产品从"Demo感"升级为"真实可用感"

## 升级方向二：完善后端分析服务，构建前后端完整链路 🔴 高优先级

### 现状问题
- `server/` 目录下已有基础Node.js服务（`server.js`、`analysis.js`），但功能简单
- 前端与后端未深度集成，分析逻辑主要在前端
- 缺少真正的图像处理和分析能力

### 复赛评分影响
| 评分维度 | 影响程度 | 说明 |
|----------|---------|------|
| **技术实现** | 🔴 严重 | 官方要求"技术架构清晰，AI链路可验证"，前后端分离是加分项 |
| **产品完成度** | 🟡 中等 | 完整的后端服务能支撑更复杂的分析逻辑 |
| **创新性** | 🟢 轻微 | 架构设计体现了工程化思维 |

### 升级策略

**短期目标（复赛阶段）**：
1. **完善后端分析接口**
   - 实现图片上传和基础图像分析接口
   - 返回构图、色彩、原创性分析结果
   - 即使分析逻辑仍是模拟的，也要有完整的请求-响应链路

2. **前端对接后端**
   - 修改 `analysisService.ts`，支持调用后端API
   - 增加 loading 状态和错误处理
   - 实现前端 fallback（后端不可用时使用前端模拟）

3. **部署后端服务**
   - 将后端服务部署到 Vercel/Render/Railway 等免费平台
   - 确保评审期间服务稳定可用

**实现要点**：
- 后端使用 Express + 基础图像处理库（如 sharp）
- 分析结果可基于图片实际特征（尺寸、主色调、对比度等）计算
- API 设计符合 RESTful 规范
- 增加请求日志，便于核验

### 预期效果
- ⬆️ 技术实现评分提升 20-25%
- ⬆️ 产品完成度评分提升 10-15%
- ⬆️ 展示了完整的工程化能力，区别于纯前端Demo
- ⬆️ 为后续迭代（真实AI接入）打下基础

### 升级策略

**视频内容规划（3-5分钟）**：

| 时间段 | 内容 | 目的 |
|--------|------|------|
| 0:00-0:30 | 产品定位与价值 | 让评审快速理解"这是什么" |
| 0:30-1:30 | 核心功能演示：AI诊断 | 展示完整诊断流程和报告效果 |
| 1:30-2:30 | 特色功能演示：灵感嫁接 + 情绪画布 | 展示差异化和创新性 |
| 2:30-3:30 | 辅助功能：素材库 + 成长追踪 | 展示产品完整性和闭环 |
| 3:30-4:30 | 技术架构与TRAE实践 | 展示技术实现和开发过程 |
| 4:30-5:00 | 总结与展望 | 强化产品价值和社会意义 |

**制作要点**：
1. **使用真实产品录屏**：不要演示模拟数据，要用真实上传的图片展示
2. **旁白/字幕说明**：每个操作都要有清晰说明，假设评审第一次看
3. **突出差异化**：重点展示"按创作形式差异化诊断"和"灵感嫁接标准系统"
4. **展示TRAE开发过程**：穿插TRAE对话截图，证明使用TRAE开发
5. **控制节奏**：不要过快，确保评审能看清每个界面和内容
6. **背景音乐**：可选，保持专业感，不要喧宾夺主

**技术准备**：
- 使用 OBS / ScreenFlow / 剪映 等工具录制
- 确保录制环境网络稳定，产品加载流畅
- 提前准备测试图片和操作流程脚本
- 导出为 MP4 格式，1080p 分辨率，控制在 100MB 以内

## 升级方向四：完善用户闭环与功能联动 🟡 中优先级

### 现状问题
- 各功能模块相对独立，缺少有机联系
- 用户从"诊断"到"改进"的路径不清晰
- 缺少引导用户持续使用的机制

### 复赛评分影响
| 评分维度 | 影响程度 | 说明 |
|----------|---------|------|
| **产品完成度** | 🟡 中等 | 完整的用户闭环体现了产品的完整性 |
| **用户体验** | 🟡 中等 | 流畅的用户路径提升易用性 |
| **创新性** | 🟢 轻微 | 闭环设计体现了产品思维 |

### 升级策略

**1. 诊断→改进→再诊断闭环**
- 在诊断报告页增加"前往灵感嫁接获取改进灵感"按钮
- 在诊断报告页增加"使用情绪画布调整情绪表达"按钮
- 在灵感嫁接/情绪画布结果页增加"重新诊断查看改进效果"按钮

**2. 素材库与诊断联动**
- 诊断报告中推荐相关素材库作品（如"参考这几幅作品的构图方式"）
- 素材库作品可一键加入灵感嫁接的选择区

**3. 首次使用引导**
- 增加首次访问的功能引导（如简单的步骤提示）
- 在关键页面增加功能说明 Tooltip

**4. 操作反馈优化**
- 增加更多成功/错误提示（Toast 通知）
- 增加操作确认对话框（如删除记录时）
- 增加 loading 动画和骨架屏

### 预期效果
- ⬆️ 产品完成度评分提升 10-15%
- ⬆️ 用户体验评分提升 15-20%
- ⬆️ 评审体验产品时路径更清晰，印象更好

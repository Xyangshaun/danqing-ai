## 一、占用类型说明

| 标记 | 含义 | 冲突规则 |
| --- | --- | --- |
| `—` | 未占用 | 无冲突 |
| `R` | 只读占用 | R × R 无冲突;R × W 无冲突;R × X 无冲突 |
| `W` | 写入占用 | W × W **冲突**;W × X **冲突**;W × R 无冲突 |
| `X` | 独占占用 | X × 任何 **冲突**(含 R) |

> **冲突判定核心规则**:同一资源上,若存在 ≥2 个任务标记为 `W` 或 `X`,则判定为冲突。
> 例外:同一任务的同一资源多次 W 不算冲突。

## 五、检测流程

### 5.1 触发时机

| 事件 | 是否触发检测 | 说明 |
| --- | --- | --- |
| 新任务创建 | ✓ 必须 | 在 active-tasks.md 登记 + conflict-matrix.md 声明后 |
| 任务资源声明变更 | ✓ 必须 | 资源占用列发生变化时 |
| 任务状态变更 | ✓ 必须 | 启动/阻塞/完成时 |
| 日常同步 | ✓ 建议 | 每日检查是否有未处理冲突 |
| 任务步骤完成 | ✗ 不需要 | 步骤级变更不触发资源变更 |

### 5.2 检测步骤

1. 读取本文件第二节「资源清单」
2. 遍历每个资源行
3. 统计该资源上各任务的占用标记
4. 应用冲突判定规则(第一节占用类型说明)
5. 若发现冲突,记录到第三节「冲突清单」
6. 同步更新第四节「并行执行矩阵」
7. 通知相关任务负责人(在任务 changelog 追加 blocked 记录)

### 5.3 手动检测清单

每次任务创建或资源变更后,按以下清单逐项检查:

- [ ] 新任务的 W 资源是否与现有任务的 W 资源重叠?
- [ ] 新任务的 X 资源是否与现有任务的任何资源重叠?
- [ ] 新任务是否修改了被其他任务调用的 API 契约?
- [ ] 新任务是否变更了被其他任务查询的数据库表 schema?
- [ ] 新任务的生产部署是否与现有任务部署窗口重叠?
- [ ] 新任务是否依赖尚未完成的任务产出?

## 六、维护规则

1. **新增任务时**:在所有相关资源行追加新任务列,填写占用标记
2. **任务资源变更时**:更新对应资源行的占用标记
3. **任务归档时**:删除该任务列,若该资源已无任何任务占用,可保留行(标记全部为 `—`)或删除行
4. **冲突解除时**:在「冲突清单」中将对应行状态改为 🟢 已解除
5. **每次更新后**:修改顶部的「最后更新」时间戳与「当前冲突数」
